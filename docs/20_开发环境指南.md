# Agora-BBS 项目本地开发环境指南

本文档用于指导新成员快速搭建 **Agora-BBS** 的全套本地开发环境。系统采用全容器化编排，本地仅需安装 Git 与 Docker 即可一键拉起包含前端、后端 API、异步 Worker、数据库及工作流引擎在内的全部服务。
## 1. 准备工作

请确保本地宿主机已安装以下基础工具：

| **工具名称**           | **推荐版本**             | **说明**   |
| ------------------ | -------------------- | -------- |
| **Git**            | 2.30+                | 版本控制     |
| **Docker**         | Docker Desktop 24.0+ | 容器运行时    |
| **docker-compose** | v2.20+               | 容器集群编排工具 |

> **注意**：本地无需单独安装 Go、Node.js、PostgreSQL、Redis 或 Temporal，所有运行时与依赖均已内置于容器内。

---

│   └── .air.worker.toml      # Worker 服务热重载配置

## 3. 一键启动开发环境

### 第一步：克隆仓库与初始化配置

```Bash
git clone https://github.com/SunnyXD365/Agora-BBS.git
cd Agora-BBS

# 复制环境变量配置文件（TODO）
cp backend/.env.example backend/.env
```

### 第二步：拉起容器集群

在项目根目录下运行以下指令

```Bash
docker compose -f docker-compose.dev.yml up -d
```

### 第三步：确认容器运行状态

```Bash
docker ps
```

确保以下 **8 个容器** 均为 `Up` 状态：
- `agora-nginx` (网关)
- `agora-frontend` (前端)
- `agora-backend-api` (后端 API)
- `agora-backend-worker` (异步 Worker)
- `agora-temporal` & `agora-temporal-ui` (工作流引擎及其看板)
- `agora-postgres` & `agora-redis` (数据存储与缓存)

## 5. 日常开发与热重载

容器环境已配置挂载卷与热重载工具，无需在修改代码后手动重启容器：

- **前端开发 (Next.js)**：修改 `frontend/` 下的代码，浏览器会自动应用热更新。
- **后端开发 (Go API / Worker)**：修改 `backend/` 下的 Go 代码，容器内的 `Air` 工具会自动重新编译并拉起服务。

### 查看服务实时日志

若代码编译报错或需排查问题，可使用以下命令查看特定容器日志：

```Bash
# 查看后端 API 编译/运行日志
docker logs -f agora-backend-api

# 查看 Worker 日志
docker logs -f agora-backend-worker

# 查看前端日志
docker logs -f agora-frontend
```

## 6. 常见日常开发操作指南

### 6.1 进入容器内部 Shell

当需要手动在容器内运行指令（例如调试环境、查看文件分布）时，使用 `podman exec`：

```bash
# 进入后端 API 容器
docker exec -it agora-backend-api /bin/sh

# 进入前端容器
docker exec -it agora-frontend /bin/sh

# 进入 Postgres 数据库终端
docker exec -it agora-postgres psql -U agora_user -d agora_db

```

---

### 6.2 如何添加/更新三方依赖库

由于本地项目目录已挂载至容器内部，**添加依赖有两种方式：

#### 方式一：直接在宿主机执行（宿主机若有 Go / Node 环境）

在本地终端进入对应目录安装，修改会自动通过卷挂载同步至容器内：

* **Go 后端**：
```bash
cd backend
go get github.com/gin-gonic/gin@latest

```


* **前端**：
```bash
cd frontend
pnpm add axios

```



#### 方式二：在容器内部执行（宿主机无需 Go/Node 环境）

直接在运行中的容器内安装，`go.mod` / `package.json` 会同步回宿主机：

* **Go 后端**：
```bash
docker exec -it agora-backend-api go get github.com/gin-gonic/gin@latest

```

* **前端**：
```bash
docker exec -it agora-frontend npm install axios

```

---

### 6.3 单个容器重启与重建

当修改了配置文件（如 `.env` 或 `nginx.conf`）或依赖冲突、热重启未生效时，无需重构整个环境：

```bash
# 重启指定服务（如只重启 Nginx 或 API）
docker compose -f docker-compose.dev.yml restart agora-nginx

# 单独重建并拉起指定服务
docker compose -f docker-compose.dev.yml up -d --build agora-backend-api

```

## 8. 容器集群架构：网络与存储卷挂载详解

为解答“修改代码为何能实时生效”以及“服务间如何通信”，以下是容器层的架构细节：

```
[ 宿主机 浏览器 / Terminal ]
          │
     :8080│ (Port Mapping)
          ▼
┌────────────────────────────────────────────────────────────────────────┐
│ agora-network (容器内部 Bridge 自定义网络)                               │
│                                                                        │
│   ┌─────────────┐   /api/*   ┌───────────────────┐                     │
│   │ agora-nginx ├───────────►│ agora-backend-api │                     │
│   └──────┬──────┘            └─────────┬─────────┘                     │
│          │ /*                          │                               │
│          ▼                             ▼                               │
│   ┌────────────────┐         ┌───────────────────┐   ┌──────────────┐ │
│   │ agora-frontend │         │agora-backend-worker──►│agora-temporal│ │
│   └────────────────┘         └─────────┬─────────┘   └──────────────┘ │
│                                        │                               │
│                                        ▼                               │
│                              ┌───────────────────┐                     │
│                              │  agora-postgres   │                     │
│                              │    agora-redis    │                     │
│                              └───────────────────┘                     │
└────────────────────────────────────────────────────────────────────────┘

```

### 8.1 容器网络通信机制

* **内部 DNS 自动解析**：所有容器均加入在 `agora-network` 网络中。服务间通信**无需使用 IP**，直接使用 **容器服务名** 作为 Host 访问。
* 例如：Backend 内部连接数据库地址为 `agora-postgres:5432`，连接 Redis 为 `agora-redis:6379`，连接 Temporal 为 `agora-temporal:7233`。


* **反向代理路由**：对外仅暴露 `agora-nginx` 的 `8080` 端口。Nginx 内部配置将请求转发至内部容器：
* `http://agora-frontend:3000`（前端页面）
* `http://agora-backend-api:8080`（后端 API）

### 8.2 存储卷映射 (Volumes & Bind Mounts) 映射关系表

容器通过两种存储挂载方式保证“代码修改即时生效”与“数据持久化不丢失”：

| 挂载类型 | 宿主机物理路径 | 容器内挂载路径 | 作用与机制 |
| --- | --- | --- | --- |
| **Bind Mount** | `./backend` | `/app` (API & Worker) | **代码热重载**：宿主机修改 Go 代码，容器内实时同步并触发 Air 重新编译。 |
| **Bind Mount** | `./frontend` | `/app` (Frontend) | **前端热更新**：宿主机修改 React/Next.js 代码，自动触发 HMR 实时刷新页面。 |
| **Bind Mount** | `./nginx/nginx.dev.conf` | `/etc/nginx/nginx.conf` | **网关配置**：修改本地 Nginx 配置文件后重启 Nginx 容器即可生效。 |
| **Named Volume** | `go_pkg_mod` (Podman 管理) | `/go/pkg/mod` | **Go 依赖缓存**：缓存已下载的 Go 模块，避免每次启动或拉起容器重新下载依赖。 |
| **Named Volume** | `postgres_data` (Podman 管理) | `/var/lib/postgresql/data` | **持久化数据库**：保证运行 `podman-compose down` 后，数据库中的测试数据不会丢失。 |

> **提示**：如果想彻底清空数据库重新建表，可以运行 `podman-compose -f docker-compose.dev.yml down -v`（`-v` 会同时删除命名的数据库持久化卷）。
