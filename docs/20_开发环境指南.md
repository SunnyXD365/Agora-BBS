# Agora-BBS 开发环境指南

本项目采用全容器化开发。宿主机只需要 Git、Docker Desktop 和 Compose；Go、Node.js、PostgreSQL、Redis、Temporal、Playwright 与 k6 均在容器中运行。

## 1. D 盘约束

本机已确认 Docker Desktop 安装在 `D:\Programs\Docker`，数据根目录在 `D:\DockerData`。因此镜像、容器、数据库卷和依赖缓存均落在 D 盘。不要在宿主机另行安装 Go、Node、PostgreSQL 或测试工具。

检查 Docker 数据目录：

```powershell
docker info --format '{{json .DockerRootDir}}'
```

如果输出不是 D 盘路径，先停止本项目，不要拉取镜像；在 Docker Desktop 的 Settings → Resources → Advanced 中迁移 Disk image location 后再继续。

## 2. 首次启动

在项目根目录执行：

```powershell
Copy-Item backend/.env.example backend/.env
docker-compose -f docker-compose.dev.yml up -d
docker-compose -f docker-compose.dev.yml ps
```

在 `backend/.env` 填入本地 LLM 配置；该文件被 Git 忽略：

```dotenv
LLM_BASE_URL=https://provider.example/v1
LLM_MODEL=your-model
LLM_API_KEY=your-key
```

管理员登录采用邮箱验证码。开发环境不配置 SMTP 时，统一登录页会显示本地演示验证码。项目提供了可直接复制的 QQ 邮箱模板 `backend/.env.smtp.qq.example`；请把配置复制到被 Git 忽略的 `backend/.env` 后填写：

```dotenv
SMTP_HOST=smtp.qq.com
SMTP_PORT=587
SMTP_USERNAME=your-account@qq.com
SMTP_PASSWORD=replace-with-qq-smtp-authorization-code
SMTP_FROM=your-account@qq.com
```

`SMTP_PASSWORD` 必须填写 QQ 邮箱设置中生成的 SMTP 授权码，不是 QQ 登录密码。生产环境必须配置 SMTP，验证码 10 分钟有效且最多尝试 5 次。授权码与 LLM Key 一样不得提交；不要把真实授权码写进 `.env.example` 或 `.env.smtp.qq.example`。

修改 `.env` 后必须重建 API 与 Worker，再重载网关：

```powershell
docker-compose -f docker-compose.dev.yml up -d --force-recreate agora-backend-api agora-backend-worker
docker-compose -f docker-compose.dev.yml restart agora-nginx
```

数据库迁移由 API 启动时自动执行，只增加新版本，不修改历史 `000001`，也不会清空已有数据。

## 4. 服务地址

| 服务 | 地址 |
| --- | --- |
| 论坛统一入口 | <http://localhost:8080> |
| 网关健康检查 | <http://localhost:8080/api/ping> |
| API 直连 | <http://localhost:8081/api/v1/ping> |
| Temporal UI | <http://localhost:8233> |
| PostgreSQL | `localhost:5432` |
| Redis | `localhost:6379` |

正常开发环境包含 8 个常驻容器：Nginx、Frontend、API、Worker、PostgreSQL、Redis、Temporal、Temporal UI。`agora-e2e` 和 `agora-k6` 使用 `test` profile，仅测试时创建。

## 5. 常用操作

```powershell
# 查看状态和日志
docker-compose -f docker-compose.dev.yml ps
docker-compose -f docker-compose.dev.yml logs -f agora-backend-api agora-backend-worker

# 停止但保留数据库卷
docker-compose -f docker-compose.dev.yml down

# 再次启动
docker-compose -f docker-compose.dev.yml up -d

# 后端测试与静态检查
docker-compose -f docker-compose.dev.yml exec -T agora-backend-api sh -c "go test ./... && go vet ./..."

# 前端检查与生产构建
docker-compose -f docker-compose.dev.yml exec -T agora-frontend sh -c "npm run lint && npm run build"
```

修改 Go/Next.js 源码通常由 Air/Next 自动热重载。新增文件、修改 Compose、Nginx 或 `.env` 后应重启相应服务。

不要随意执行 `down -v`：它会删除 PostgreSQL 和 Redis 数据卷。确需清库时先备份并明确确认。

## 6. 在容器中管理依赖

```powershell
# Go 依赖
docker-compose -f docker-compose.dev.yml exec -T agora-backend-api go get module@version

# 前端依赖
docker-compose -f docker-compose.dev.yml exec -T agora-frontend npm install package@version
```

这样依赖缓存位于 Docker 的 D 盘数据区，不会使用宿主机 C 盘的 Go/Node 缓存。

## 7. 管理员与生产环境

开发 Seed 提供管理员。生产环境先正常注册用户，再执行容器内命令提升：

```powershell
docker-compose -f docker-compose.prod.yml --env-file .env.production exec agora-backend-api /app/admin -username your_name -action promote
```

降级使用 `-action demote`。该命令不创建默认密码，也不修改正文。

生产配置：

```powershell
Copy-Item .env.production.example .env.production
# 编辑强密码、JWT_SECRET 和 LLM 配置
docker-compose --env-file .env.production -f docker-compose.prod.yml up -d --build
```

完整部署、备份、测试和故障排查见 `docs/60_测试部署与运维.md`。

## 8. 常见故障

- `502 Bad Gateway`：先确认 API/Frontend 健康，再 `docker-compose ... restart agora-nginx`。当前 Nginx 会动态重新解析容器地址。
- API 启动失败：查看 API 日志；若迁移显示 `dirty=true`，不要自行强制改版本，先保存日志并检查失败 SQL。
- Worker 无任务：确认日志包含 `polling task queue "agora-governance"`，并在 Temporal UI 查看工作流。
- LLM 失败：后台查看 `llm_jobs` 的状态和脱敏错误，修正本地配置后点击“安全重试”。
- 页面登录失效：401 会清除本地 Token，重新登录即可。
