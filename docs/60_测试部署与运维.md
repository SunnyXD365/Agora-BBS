# Agora-BBS 测试、部署与运维

## 1. 自动化验证

所有工具均通过 Docker 运行，宿主机无需安装 Go、Node、Playwright 或 k6。

```powershell
# Go 单元测试、Temporal 时间跳跃测试和静态检查
docker-compose -f docker-compose.dev.yml exec -T agora-backend-api sh -c "go test ./... && go vet ./..."

# 前端 ESLint、TypeScript 和生产构建
docker-compose -f docker-compose.dev.yml exec -T agora-frontend sh -c "npm run lint && npm run build"

# 端到端治理流程
docker-compose -f docker-compose.dev.yml --profile test run --rm agora-e2e

# 20 req/s 的快速压测
docker-compose -f docker-compose.dev.yml --profile test run --rm agora-k6
```

常规 E2E 覆盖注册、L0 初始态、自述、主题与论坛使用手册的阅读结算、冷静期创建与撤回、语境反馈、三人任务选择、两票盲审、管理统计、管理列表的搜索/筛选/排序、用户编辑及其审计流水和后台页面。

### L0 到 L3 成长旅程专项测试

`backend/seed.sql` 会生成 Go、并发、社区治理和 Coding Agent 主题，包含普通短文、普通中篇、800 字以上长文，以及正文较短但分类为高争议的主题。它还会仅重置 `demo_l0` 的成长验收数据；生产环境禁止执行。

专项测试按真实 5 秒心跳和 60 秒冷静期运行，约需 5 至 6 分钟：

```powershell
Get-Content backend/seed.sql -Raw | docker exec -i agora-postgres psql -v ON_ERROR_STOP=1 -U agora_user -d agora_db
docker-compose -f docker-compose.dev.yml --profile test run --rm -e RUN_GROWTH_JOURNEY=1 agora-e2e sh -lc "npm ci && npx playwright test growth-journey.spec.ts"
```

测试依次验证 L0 回复被拒绝、自述两票通过、普通短文完成后升 L1、5 条回复经过 Temporal 冷静期发布、中篇完成后升 L2、长文完成停留门槛后升 L3，以及高争议短文未停留时不能完成。2026-09-13 本机实测 5.4 分钟通过，最终状态为 L3、有效阅读 310 秒、合规互动 5、信任分 20、自述 `approved`。

## 2. k6 性能测试

脚本位于 `tests/load/forum.js`，一次迭代批量读取主题、分类和公开治理策略。阈值为错误率 `<1%`、P95 `<500ms`。

完整目标测试先用 2 分钟升压到约 1000 HTTP req/s，再保持 5 分钟：

```powershell
$env:K6_PROFILE='full'
$env:K6_RATE='334'
docker-compose -f docker-compose.dev.yml --profile test run --rm agora-k6
Remove-Item Env:K6_PROFILE
Remove-Item Env:K6_RATE
```

每次迭代包含 3 个 HTTP 请求，因此 334 次迭代/秒对应约 1000 HTTP 请求/秒。原始摘要输出到本地忽略目录 `tests/load/results/latest-summary.json`，不要只保留终端截图。

## 3. 生产部署

```powershell
Copy-Item .env.production.example .env.production
# 编辑 .env.production，使用 URL 安全的数据库强密码、随机 JWT Secret、真实 LLM 凭据和 SMTP 邮件配置
docker-compose --env-file .env.production -f docker-compose.prod.yml config
docker-compose --env-file .env.production -f docker-compose.prod.yml up -d --build
docker-compose --env-file .env.production -f docker-compose.prod.yml ps
```

生产编排使用独立项目名 `agora-bbs-prod` 和独立数据卷，不会复用开发数据库。它仅公开 Nginx `HTTP_PORT`（默认 `8080`）；Temporal UI 只绑定 `127.0.0.1:TEMPORAL_UI_HOST_PORT`（默认 `8233`），PostgreSQL 和 Redis 不暴露宿主机端口。若开发环境仍在运行，请先停止开发环境，或为生产配置不同的两个宿主机端口。API 和 Frontend 均有健康检查，Worker 自动重启。

生产环境不执行 `seed.sql`。注册首个账号后提升管理员：

```powershell
docker-compose --env-file .env.production -f docker-compose.prod.yml exec agora-backend-api /app/admin -username your_name -action promote
```

被提升账号必须已经填写有效邮箱。管理员每次密码登录后都要完成 6 位邮箱验证码；生产环境 SMTP 缺失或投递失败时不会签发管理 Token。建议使用支持 STARTTLS 的 587 端口，并将 SMTP 密码仅保存在被 Git 忽略的 `.env.production`。

## 4. 数据备份与恢复

备份不会停止服务，但高一致性要求时应安排维护窗口：

```powershell
docker exec agora-postgres pg_dump -U agora_user -d agora_db -Fc -f /tmp/agora.dump
docker cp agora-postgres:/tmp/agora.dump D:\AgoraBackups\agora.dump
```

恢复前必须确认目标库和备份文件，建议恢复到新的数据库进行校验。不要在未备份时执行 `docker-compose down -v`。

Redis 只保存可重建缓存和限流状态，不作为业务事实备份；Temporal 和业务表都依赖 PostgreSQL 数据卷。

## 5. 监控与故障处理

- `/api/ping`：API 存活；Compose 健康检查使用该接口。
- Temporal UI：查看冷静期、盲审、抽检和聚类的历史、重试与失败原因。
- 管理后台：查看内容状态、信任分布/流水、盲审完成情况及 LLM 调用、延迟、Token 和失败作业。
- `docker-compose ... logs --tail=200 SERVICE`：检查启动和运行错误。
- `docker stats --no-stream`：记录 CPU、内存和网络压力。

Redis 不可用时 API 的缓存和限流采用失败开放，业务读取回退 PostgreSQL；PostgreSQL 或 Temporal 不可用会阻止需要一致性/持久调度的操作。LLM 调用失败由有限指数重试处理，最终状态写入 `llm_jobs`，修复配置后由管理员安全重试。
