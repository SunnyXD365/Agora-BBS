# Agora-BBS 已知问题与待办

本文档记录测试过程中发现的问题、处理方式和验收结果。

## P1：有效阅读时长未及时结算

- 记录日期：2026-09-13
- 当前状态：已修复
- 关闭日期：2026-09-13
- 影响范围：主题阅读、成长中心、首页成长进度卡片
- 发现账号：`hxshr`

### 问题现象

用户完整阅读一篇普通短文约 3 分钟后，成长中心的“有效阅读时长”仍显示为 0 分钟。

### 已确认的现场数据

- 最新阅读会话已记录约 195 秒，滚动进度为 100%，但回复区停留时间只有 5 秒。
- 该会话仍为未完成状态，因此 195 秒没有汇总到用户的有效阅读总时长。
- 用户此前已有 20 秒有效阅读；前端使用向下取整的分钟数展示，所以 20 秒仍显示为 0 分钟。

### 根因

1. 前端当前对所有主题都要求“滚动到底且回复区停留达到配置时长”后才调用阅读完成接口。
2. 设计规则原本只要求长文或高争议主题满足回复区停留门槛，普通短文不应受该条件限制。
3. 后端仅在阅读完成接口成功执行后，才把会话时长汇总到用户的有效阅读总时长。
4. 页面离开时没有可靠结算已经满足条件的阅读会话，未完成会话中的时长可能长期停留在会话表中。
5. 少于 60 秒的有效阅读被前端直接显示为 0 分钟，容易让用户误以为完全没有记录。

### 修复内容

1. 由服务端统一判断主题是否需要回复区停留，普通主题滚动到底即可完成；800 字以上长文和高争议分类继续执行双重门槛。
2. 完成接口接收浏览器最后的滚动与聚焦状态，页面离开时使用 `keepalive` 请求安全收尾。
3. 未满足规则的完成请求只保存最新进度，不关闭会话、不汇总时长；再次打开同一主题会续接最近的未完成会话。
4. 完成与汇总保持事务和幂等，只有首次满足规则时才把本次阅读秒数加入用户档案。
5. 成长中心、首页侧栏和管理端按秒、分钟或小时显示时长，不再把不足 60 秒显示成“0 分钟”。

### 验收标准

- 普通短文滚动到底后，阅读会话能够完成并汇总有效时长。
- 长文或高争议主题只有在滚动到底且达到配置的回复区停留时间后才完成。
- 页面跳转、刷新或重复发送完成请求不会丢失时长，也不会重复累计。
- 用户有效阅读不足 60 秒时，界面不再显示具有误导性的“0 分钟”。
- 后端单元测试或接口测试覆盖普通主题、受限主题、重复完成和未完成会话场景。

### 验收结果

- 后端完整测试通过，新增普通主题与受限主题资格判定单元测试。
- 前端 ESLint、TypeScript 和生产构建通过。
- Playwright 常规回归 4 项通过（另有 1 项专项测试按环境变量跳过），成长旅程专项测试 1 项通过，用时 5.4 分钟。
- `demo_l0` 从 L0 完成 65 秒短文、125 秒中篇和 120 秒长文阅读，5 条回复经过真实冷静期发布，自述完成两票盲审，最终达到 L3。
- 最终数据为有效阅读 310 秒、合规互动 5、信任分 20、自述 `approved`。
- 162 字高争议短文在滚动到底但未停留回复区时保持 `eligible=false`、`completed=false`，没有进入有效阅读汇总。

### 历史会话处理

没有直接改写包括 `hxshr` 在内的历史汇总时长，也没有删除历史阅读会话。用户重新进入原主题时会续接最近的未完成会话；满足新规则后的首次完成请求会正常、且仅一次汇总已有会话时长。
