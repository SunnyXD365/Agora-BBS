# Agora-BBS 已知问题与待办

本文档记录测试过程中发现、但尚未进入修复阶段的问题。问题修复后应补充对应提交、测试结果与关闭日期。

## P1：有效阅读时长未及时结算

- 记录日期：2026-09-13
- 当前状态：待修复
- 影响范围：主题阅读、成长中心、首页成长进度卡片
- 发现账号：`hxshr`

### 问题现象

用户完整阅读一篇普通短文约 3 分钟后，成长中心的“有效阅读时长”仍显示为 0 分钟。

### 已确认的现场数据

- 最新阅读会话已记录约 195 秒，滚动进度为 100%，但回复区停留时间只有 5 秒。
- 该会话仍为未完成状态，因此 195 秒没有汇总到用户的有效阅读总时长。
- 用户此前已有 20 秒有效阅读；前端使用向下取整的分钟数展示，所以 20 秒仍显示为 0 分钟。

### 根因

1. 前端当前对所有主题都要求“滚动到底且回复区停留达到配置时长”后才调用阅读完成接口。
2. 设计规则原本只要求长文或高争议主题满足回复区停留门槛，普通短文不应受该条件限制。
3. 后端仅在阅读完成接口成功执行后，才把会话时长汇总到用户的有效阅读总时长。
4. 页面离开时没有可靠结算已经满足条件的阅读会话，未完成会话中的时长可能长期停留在会话表中。
5. 少于 60 秒的有效阅读被前端直接显示为 0 分钟，容易让用户误以为完全没有记录。

### 计划修复

1. 普通短文滚动到底后即可完成阅读；长文或高争议主题继续执行“滚动到底 + 回复区停留”的双重门槛。
2. 增加安全的会话收尾机制，避免切换页面或关闭页签时丢失已满足规则的阅读时长。
3. 保证完成接口和时长汇总幂等，防止重复请求造成重复累计。
4. 优化不足 1 分钟的展示方式，显示秒数或“少于 1 分钟”。
5. 为既有未完成会话制定可审计、不会重复计时的恢复方案。

### 验收标准

- 普通短文滚动到底后，阅读会话能够完成并汇总有效时长。
- 长文或高争议主题只有在滚动到底且达到配置的回复区停留时间后才完成。
- 页面跳转、刷新或重复发送完成请求不会丢失时长，也不会重复累计。
- 用户有效阅读不足 60 秒时，界面不再显示具有误导性的“0 分钟”。
- 后端单元测试或接口测试覆盖普通主题、受限主题、重复完成和未完成会话场景。

### 数据处理约束

修复逻辑完成前不直接修改用户汇总时长，也不删除现有阅读会话。后续如需补算历史会话，应通过可重复执行、可审计且具备去重保护的数据迁移或管理命令完成。
